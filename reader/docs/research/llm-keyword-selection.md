# 点睛阅读「点亮重点词」：用大模型选词能不能到 80%

> 2026-10-07。接 `entropy-keyword-highlighting.md`（离线统计算法，旧口径 P@50 ≈ 0.52）。
> 负责人的目标：点睛阅读点亮的词，准确率到 80% 以上。可以用 AI 预处理（优先硅基流动的免费模型），也可以利用大模型「读过」名著的记忆，或者换更好的算法。
> 原型：`docs/research/prototypes/llm-keywords/`（脚本 + 新金标 `gold/` + 人工裁决记录 `gold/adj/`）。本文没有改动 `src/`。

---

## 0. 结论

**到了，但要换一个前提：按内容决定点亮多少，而不是固定点亮 8% 的词。**

| | 统计算法（基础版现状） | **大模型按块读正文挑词（B）** | 只凭书名回忆（C） |
|---|---|---|---|
| 点亮的词次里，该亮的占比（hit） | 0.46（固定 8%）/ 0.67（固定 4%） | **0.94**（V4-Flash）/ **0.91**（5 个免费模型投票）/ 0.91（单个 Qwen3-8B） | 0.96，但只覆盖 0.26 |
| 点亮的词种里，该亮的占比 | 0.29 | **0.83** / 0.79 / 0.78 | 0.90 |
| 分数最高的 50 个词（P@50） | 0.76 | **0.97** / 0.95 / 0.92 | 0.53 |
| 反复出现的重点词至少亮一次（recK） | 0.73 | 0.67 / 0.70 / 0.58 | 0.26 |
| 实际点亮密度（占词数） | 7.7% | 3.9% / 4.1% / 3.6% | 2.3% |

（6 个文本平均：小说《阿Q正传》、科普「黑洞」、技术「TCP」、整本《呐喊》、整本《老残游记》、冷门文言小说《断鸿零雁记》。金标见 §2。）

1. **方法 B 达标。** 把正文按约 3,000 字分块，让模型直接挑出「人名、地名、术语、核心概念、关键物件」，客户端在原文里精确定位，再套用原有的排布规则（每句上限、不相邻、一段只亮一次、首次强调）。V4-Flash 点亮的词次有 94% 是该亮的，词种 83%。**完全免费的方案也能到 80% 以上**：5 个免费模型里至少 2 个都选中的词，词次 91%、词种 79%；单个 Qwen3-8B 是 91% / 78%。
2. **固定 8% 的密度，任何方法都到不了 80%。** 这和选法无关：如果只点亮标注为正例的词（上限 O），平均也只能点亮 5.3% 的词，小说只有 3.5%–5.0%。小说里值得点亮的词本来就少，要凑满 8%，只能加进普通词。所以密度滑条应当是**上限**，不是目标：AI 选出多少就亮多少，读者选「多」时才用统计词补满，补进去的词用弱样式。
3. **「凭记忆列出名著关键词」不能单独用。** 模型列出的词，有 32%（V4-Flash）到 60%（Qwen3-8B）在正文里根本不存在，例如《阿Q正传》里的「精神胜利法」，TCP 条目里的「四次挥手」；冷门的《断鸿零雁记》，三个免费模型列出的词全部不在书里（把作者错当成「弘一」「李叔同」）。对 4 本书（包括冷门书），所有模型都自称「读过」，所以没法让模型自己判断要不要回答。过滤掉不在书中的词以后，剩下的词很准（0.96），但只覆盖约四分之一的重点词。
4. **其他想法的效果。** 让模型从统计算法的前 400 个候选里挑词（E，只发词表、不发正文）：V4-Flash 达到 0.83，但覆盖率只有 0.49，免费模型只有 0.66。KeyBERT 式嵌入中心度（bge-m3）基本无效（0.29），在小说里挑出来的是「岂不是、玩笑、啥事」。统计算法发现的新词，对 B 几乎没有补充，因为人名模型都已经找到了。
5. **旧金标的问题。** 旧的 60 词左右的列表只有一位 AI 标注者。用另外两个强模型独立重标后，各列表之间的 Jaccard 只有 0.27–0.53；即使只点亮新金标的正例，按旧列表算 P@50 也只有 0.57。所以旧文档里的 0.52 主要受限于标注本身，看不出方法之间的差别。本文改用**逐词判定**的金标：两个模型的 Cohen κ = 0.62–0.71（较一致），分歧由我逐条裁决（§2）。

**推荐方案（10 行内）**


## 1. 口径

- **hit（主指标）**：按某个密度点亮的全部词次里，标注为正例（≥1）的占多少。读者看到的就是这些词次。
- **词种准确率**：点亮过的不同词里，正例占多少。它不受「阿Q」这类高频人名的拉动，比 hit 更严格。
- **P@50**：分数最高的 50 个词里，有几个是正例。
- **recK**：在正文里出现 ≥3 次的正例词中，至少被点亮过一次的占多少。点亮了更长的词也算覆盖，例如亮「赵太爷」就覆盖了「太爷」。
- **密度**：点亮词次 ÷ 全书词数。统计方法按章用二分法定阈值，凑到目标密度；LLM 方法只亮模型选出的词，所以密度由内容决定，目标值只作为上限。
- 所有方法共用 `keyHighlight.ts` 的排布规则：每句有上限、点亮的词不相邻、同一个词在一段里只亮一次、第 k 次重复出现时分数减 ln(1+k)。

**为什么不能固定 8%**：「上限 O」只点亮标注为正例的词，各文本的密度分别是：小说 5.0%，科普 7.7%，技术 7.6%，《呐喊》3.8%，《老残游记》3.5%，《断鸿零雁记》4.2%。科普和技术文本术语多，能接近 8%；小说做不到。

## 2. 新金标：池化逐词判定 + 双模型 + 人工裁决

### 2.1 做法

1. **候选池**（TREC 式 pooling）：把所有方案在 8% 密度下点亮的词、各方案的前 50 个词、两个标注模型自由标注的词，以及旧金标，合在一起，共 7,431 个词（小说 692、科普 460、技术 512、《呐喊》1,749、《老残游记》2,544、《断鸿零雁记》1,474）。
2. **标注者 1：DeepSeek-V3.2**，标全部候选。每个词附出现次数和第一次出现处的上下文，判 2（核心）/ 1（可以）/ 0（不该点亮）。提示词要求从严：普通具体名词（嘴巴、酒钱）、跨词碎片（「大卫」其实是「大卫·芬克尔斯坦」的一部分）都判 0。
3. **标注者 2：Kimi-K2.6**，标三部分：科普全部候选；其他文本随机抽 12%；以及主要方案实际点亮的全部词（给两处上下文）。共 2,968 个词有两份标注。
4. **人工裁决（我）**：两份标注在「≥1 与 0」上不一致的 569 个词，由我逐条判定，记录在 `gold/adj/`。只有一份标注的词，沿用 DeepSeek-V3.2 的结果。
5. 选词模型和标注模型不重叠。选词用 Qwen / GLM-4-9B / Xing / DeepSeek-V4-Flash，标注用 DeepSeek-V3.2 和 Kimi-K2.6。V4-Flash 和 V3.2 同属 DeepSeek，是本研究的局限之一。

第一轮用的是宽松提示词（「有信息量的具体名词也算 1」），结果 Kimi 把「描述、解决方案、在此期间」都判成正例，这一轮全部作废。

### 2.2 一致性

**逐词判定**（二值：≥1 与 0）

| 文本 | 双标词数 | 一致率 | Cohen κ |
|---|---:|---:|---:|
| 小说 | 303 | 0.83 | 0.61 |
| 科普（全部双标） | 460 | 0.84 | 0.68 |
| 技术 | 228 | 0.82 | 0.58 |
| 《呐喊》 | 547 | 0.74 | 0.50 |
| 《老残游记》 | 869 | 0.82 | 0.63 |
| 《断鸿零雁记》 | 561 | 0.81 | 0.61 |
| **合计** | 2,968 | **0.81** | **0.62** |

只看第一轮随机抽样的部分（不含「方案点亮的词」这一难例集），κ = 0.71。分歧集中在两类词：一是情节里的物件和意象，例如《药》里的乌鸦、《社戏》里的罗汉豆，DeepSeek 偏向判 0；二是边缘人名和碎片，例如「约翰」「罗伯特」，Kimi 偏向判 1。

**自由列词**（每个标注者自己列出 core 词表，只看正文里确实出现的词）

| 文本 | V3.2 core vs Kimi core 的 Jaccard | 旧金标 vs V3.2 core | 旧金标 vs Kimi core | 旧金标被 V3.2 全表覆盖的比例 |
|---|---:|---:|---:|---:|
| 小说 | 0.44 | 0.27 | 0.29 | 0.52 |
| 科普 | 0.52 | 0.27 | 0.27 | 0.49 |
| 技术 | 0.39 | 0.29 | 0.09 | 0.61 |
| 《呐喊》 | 0.53 | 0.32 | 0.37 | 0.57 |
| 《断鸿零雁记》 | 0.39 | — | — | — |

（《老残游记》全文 10.5 万字，DeepSeek-V3.2 多次超时，没有拿到自由列表。）

结论：**让标注者自由列词，结果差别很大**，因为每个人列多少、偏向人名还是概念，都不一样。逐个判断一个词该不该亮，一致性就高得多。所以评测改为逐词判定。

- 只有在名著上，V4-Flash 的结果才比较可用（《老残游记》中 83% 的词在书里）。但 C 不读正文，覆盖率最多只有 0.5，只适合当作加分的先验。与 B 一起用（D）时，覆盖率提升不明显，所以**不推荐**。

统计算法的典型错误有三种：一是切出半个词（「铁公」）；二是点亮普通词（「朝南」「打完」）；三是「阿Q」被切成「阿 + Q」，所以永远点不亮。B 的典型错误是点亮了日常物件（长凳、条凳、油灯、洋钱），以及只出现一次的典故人名（妲己、褒姒、董卓）。

## 5. 失败模式

1. **固定密度**：小说中可点亮的词只占 3.5%–5%。凑满 8% 必然要加进普通词，统计算法在小说上的 hit 只有 0.28–0.32，原因就在这里。
2. **按块挑词再全书合并**：只在一章里重要的词，到别的章也会被点亮，例如《阿Q正传》第一章的「列传 / 内传 / 家传」。只取 r≥2 的词，hit 升到 0.98，recK 降到 0.61，相当于在「准」和「全」之间换一档。
3. **免费模型投票带进的普通名词**：例如《呐喊》的「母亲」、《老残游记》的「掌柜的」「姑娘」「省城」。投票门槛越高越准，但也越不全，见 §4.1。
4. **文言 / 冷门书**：B 仍能做到 0.91（V4-Flash）/ 0.82（免费投票），C 则完全失效。
5. **剧透**：B 每块只看当前块，不会提前提到后文。C 虽然也只点亮正文中实际出现的词，但它会在一个人物第一次出场时就把他标成重要人物，在小说里相当于轻微剧透，这也是不用 C 的原因之一。
6. **定位**：模型写的「阿 Q」、带书名号的词、全角半角混用，都要先规范化。原文如果用异体字（「和尙」「鎗毙」），而模型输出的是规范字，就会定位失败，丢掉这个词。
7. **金标偏差**：两个标注者也是大模型，它们对「重点词」的理解可能和选词模型相近，从而对 LLM 方法有利。我在裁决时抵消了一部分：「乌鸦」「罗汉豆」等意象词由 0 改为正例，「约翰」「罗伯特」等碎片由正例改为 0。即便如此，0.9 以上的数字仍应理解为「两个强模型加一个人工裁决者都认可」，而不是真实读者的评价。上线后要用读者点「不是重点」的比例来校准（§6.5）。

## 6. 生产设计

### 6.1 在哪里跑

| 选项 | 优点 | 缺点 | 建议 |
|---|---|---|---|
| **并进智能版现有分块请求**（relay → V4-Flash） | 不增加请求次数，输出约多三成（每本约 +¥0.15）；复用现有同意流程、额度、缓存、锚定 | 只有开了智能版的读者才有 | **首选** |
| 客户端单独请求（读者自己的密钥 / Ollama） | 不经过我们的服务器 | 要多一类请求 | 用读者自己的 AI 时，同样走「合并进 mark 请求」这条路 |
| 服务端预计算 + 按内容 hash 共享 | 公版书、热门书只算一次；可以用免费模型 | 服务端需要看到正文 | 只对读者已经开了智能版、正在读的书做；键是 `sha256(规范化分块文本)+promptVersion`；只存词表（每本约 5 KB），不存正文，不关联读者 |

协议的改法：在 `prompt.ts` 的 mark 模式里增加一种行类型，并提升 `PROMPT_VERSION`。

```json
{"t":"kw","q":"赵太爷","r":3}
```

规则：q 必须是本块正文里一字不差的子串，2–8 个字；只挑人物、地名、机构、术语、核心概念、关键物件；每 100 字约 1 个，宁缺毋滥。现有的 `term`（概念，带释义）仍然只标第一次出现；`kw` 只用来点亮，不带释义。

### 6.2 客户端怎么亮

1. 把各块的 `kw` 合并成本书词表，重要度取最大值，并记录这个词在几个块里被选中。
2. 切分时把本书词表当作强制词：在段落里精确定位，长词优先，不重叠；剩下的部分用原来的词表切分（`harness.ts` 的 `prepare`）。
3. 打分：S = 4r + 2·ln(被选中的块数) + K + 0.5B。K 和 B 沿用统计算法，用来在同一重要度内排序。排布规则不变。
4. 密度三档：
   - 「少」：只亮 r≥2 的 AI 词（约 3%，hit 0.98）；
   - 「标准」（默认）：亮全部 AI 词（约 4%，hit 0.94）；
   - 「多」：先亮全部 AI 词，再用统计词补到 8%（统计词用弱样式；hit 约 0.6，recK 0.87）。
5. AI 结果到达之前、离线时，或额度用完时，先显示统计结果（基础版的逻辑）。某一块的 AI 结果到了，就替换这一块，不重排已经读过的部分。

### 6.3 与基础版 / 智能版的对应

| | 基础版（不联网） | 智能版（AI） |
|---|---|---|
| 选词 | 统计 V3 | B（并进 mark 请求），统计词作为兜底和补充 |
| 默认密度 | **建议从 8% 改为 4%**（hit 0.46 → 0.67，P@50 不变） | 由内容决定，约 3%–5%；滑条是上限 |
| 准确率（本文口径） | 0.67（4%） | 0.94（词种 0.83） |
| 成本 | 0 | 每本书约多 ¥0.15 |

界面文案：不需要新增。如果要在智能版的说明里体现这个好处，可以写成 `dianjing.smartDesc` 的一个变体，按 `copy-guidelines.md` 的要求，好处放在前面，不超过 24 字，不提机制：

- 「AI 先读一遍，人名、地名和关键术语一眼就能看到」

不写「更准」这类比较级，也不写任何关于数据或统计的说明。

### 6.4 预算

- 每台设备的额度仍按现有的「每天处理字数」计算，不变。并进 mark 请求后，每 1,000 字约多 80 个输出 token（现在约 240 个）。
- 服务端共享缓存的命中率取决于书的重合度。公版和热门书越多，成本越低。
- 免费模型只用于服务端预计算和 V4-Flash 不可用时的降级，采用三选二投票。超出 TPM 时排队，不影响阅读，因为统计结果已经先显示出来了。

### 6.5 统计（默认开启，界面上不做任何说明）

上报以下数据：

- 本章 AI 覆盖率：有 AI 结果的块占多少。
- 实际点亮密度和所选档位。
- 每千个点亮词次中，读者点「不是重点」的次数。这是线上准确率的代理指标，目标是低于 20‰。
- 定位失败率：模型给的词在正文里找不到的比例，目标是低于 3%。
- AI 和统计结果之间的切换次数。

不上报正文和具体的词。

## 7. 风险

1. **准确率依赖口径**：≥80% 是在「双模型逐词判定 + 人工裁决」的金标下、按内容决定密度时测得的。如果按旧的单人列表算，所有方法都在 0.5 左右。如果按真实读者的感受算，需要上线后用「不是重点」的比例来验证。
2. **固定密度的预期**：如果产品坚持「默认 8%」，小说的准确率不可能超过约 50%，这是文本本身的上限。
3. **供应商变化**：免费模型的名单、限速和价格都会变。本次就发现 Qwen3.5-9B 不在免费名单里，DeepSeek-V3.2 的标价是 ¥4 / ¥6，而不是页面 JSON 里的 ¥2 / ¥3。所以模型名要放在服务端配置里，并纳入 `promptVersion`。
4. **隐私**：B 需要发送正文，这已经包含在智能版现有的同意流程里。服务端共享缓存会让服务端知道「有人读过这段文本」，所以只存 hash 键和词表，不关联设备，也不记录查询日志。
5. **小模型的稳定性**：会出现重复循环、套代码块、截断等问题，必须做宽松解析和截断保护，坏块直接跳过，改用统计结果。
6. **本次超支**：标注花费超出 ¥5 预算约 ¥0.7（§0）。
