# 跨章连续滚动（2026-10-07）

滚动模式下章与章首尾相接，一路滑下去不停顿、不白屏、不跳动。横屏竖屏都生效（竖屏默认滚动；横屏在排版面板选「滚动」）。翻页模式不变。

## 1. 现状与病根

foliate-js 的 `foliate-paginator` 一次只渲染一章（一个 iframe）。滚动模式下滑到章末就停住，要再推一下才 `next()`：卸掉旧 iframe → 解压新章 → 新 iframe 加载、整章排版 → 跳到新章顶部。Surface（i7-1265U, WebView2 154）实测一次切章约 300ms，其中强制布局约 80ms、原生解析与排版约 180ms，轻阅自身 JS 只占几毫秒。用户感受到的是：章末「撞墙」→ 停顿 → 画面整页替换。

所以优化轻阅的 relocate 处理没用，必须让下一章**提前**排好、**直接接在**当前章下面。

## 2. 结构

```
#container (overflow-y: auto, overflow-anchor: none)
 ├─ slot[i-1]  View(iframe 撑满整章高度)
 ├─ slot[i]    ← 当前章 (阅读线所在)
 ├─ slot[i+1]  预载好的下一章
 └─ …
```

- fork `foliate-js/paginator.js` 到 `src/vendor/foliate/paginator.js`，用一个 Vite `resolveId` 插件把 `view.js` 里的 `./paginator.js` 指向 fork。翻页模式代码原样保留；新增的只是滚动模式下的「多槽」分支。
- 每个槽就是原来的 `View`（iframe + overlayer），沿用它的 `load / render / expand`。槽之间留 `章间距 = 2 × margin`，章首本来就有标题，不另画分隔线。
- 只放线性章（`linear !== 'no'`）。

## 3. 当前章与阅读线

- **阅读线**：视口顶部往下 `size × 0.2` 处的水平线（大约是眼睛开始读的位置）。
- **当前章**：阅读线落在哪个槽，哪个槽就是当前章。滑过章界时 `#index` 切换，补发一次 `relocate`（`reason: 'scroll'`）和 `load` 之外的 `section-change` 事件。
- **滞回**：只在阅读线越过章界 8px 以上时才切换，避免停在章界附近来回抖。
- 对外 API 保持「按当前章」的语义，轻阅现有的页码、进度、目录高亮都不用改：
  - `start = scrollTop − slot.top`，`end = start + size`，`viewSize = slot.height`（当前章内的相对值）
  - `getContents()` 返回所有已载槽 `[{ index, doc, overlayer }]`，**当前章排第一**（现有代码大量用 `[0]`）
  - `relocate.detail.fraction = start / viewSize`，`index = 当前章`

## 4. 预载：按时间而不是按像素

固定「剩两屏就加载」在快速甩动时来不及，慢读时又太早。改成按「剩余内容还能撑多久」：

```
v      = 滚动速度 (px/ms)，对 scroll 事件做指数滑动平均，静止时衰减到 0
D↓     = 最后一个槽底 − 视口底          (下方还剩多少已排好的内容)
D↑     = 视口顶 − 第一个槽顶
T_load = 最近几次「解压 + iframe 加载 + 排版」耗时的滑动平均 (初值 400ms)

需要向下预载 ⇔ D↓ < max(2 × size, v × T_load × 2)
需要向上预载 ⇔ D↑ < max(1 × size, v↑ × T_load × 2)
```

- **何时动手**：只要「需要预载」就排队；队列一次只载一章。
  - 不紧急（`D > size`）且正在甩动 → `requestIdleCallback(…, { timeout: 500 })`，等主线程空闲，不在惯性滚动中间插 300ms 的排版。
  - 紧急（`D ≤ size`）→ 立即加载。
- **空闲预取**：当前章显示完、主线程空闲后，无论速度多少，都先把下一章预载好（大多数人是往下读的）；上一章等用户往上滑时再载。
- 解压（`section.load()` 得到 blob URL）比排版便宜得多，下下章的解压也可以提前做，排版留到真正插入时。

## 5. 插入与卸载：视口不能动

关键约束：**任何在视口上方发生的高度变化，都要在同一帧内用 scrollTop 抵消**，否则用户看到的内容会跳。容器设 `overflow-anchor: none`，关掉浏览器自带的滚动锚定，全部手动补偿，避免两套机制叠加。

| 操作 | 位置 | 处理 |
|------|------|------|
| 追加下一章 | 视口下方 | 直接 append，无需补偿 |
| 插入上一章 | 视口上方 | 先以高度 0 插入并加载；在它 `expand()` 得到高度 `h` 的同一回调里 `scrollTop += h`（ResizeObserver 回调在绘制前执行，用户看不到中间态） |
| 上方槽重排（字体 / 图片晚到） | 视口上方 | `onExpand` 里比较新旧高度，`scrollTop += Δh` |
| 卸载远处的章 | 上方 | `scrollTop −= h` 后移除 |
| 卸载远处的章 | 下方 | 直接移除 |

- **甩动中不动上方 DOM**：程序写 scrollTop 可能打断 Windows / iOS 的惯性。上方的插入、卸载一律等到「无触摸且 150ms 无滚动事件」再做；用户往上甩到快没内容时（`D↑ ≤ size`）才例外立即插入。
- **内存上限**：最多保留 5 个槽（当前章前后各 2 个），超出时卸载离当前章最远的；每个卸载的槽调用原来的 `section.unload()` 释放 blob。超长章节（单章 > 20 屏）只保留前后各 1 个。

## 6. 锚点与重排

foliate 原本只在滚动停下 250ms 后才更新锚点，期间若有重排（窗口尺寸变化、改字号），会把位置拉回旧锚点——这正是另一类「往回跳」的来源。新方案：

- 锚点 = 阅读线处的 Range（当前章内），**每帧**滚动时按需惰性更新（只在需要重排时才真正计算），重排前先取最新锚点。
- 窗口尺寸 / 样式变化 → 所有槽重排 → 按锚点 Range 的新位置设置 `scrollTop = slot.top + rect.top − 阅读线偏移`。
- 改字号这类全局变化，先只重排当前章并定位，其余槽在空闲时逐个重排（各自高度变化按第 5 节补偿）。

## 7. 导航

- `goTo(index, anchor)`：目标章已在槽里 → 直接滚过去（距离不超过 3 屏时平滑滚动，否则瞬间跳）；不在 → 清空所有槽，载目标章并定位，再按第 4 节预载邻章。
- `next() / prev()`（点左右区、键盘、PageDown）：按 `size × 0.9` 平滑滚动，自然跨章；书首 / 书尾停住。
- 原来轻阅为跨章写的「停在章末再推一下」手势（`crossSectionBySwipe`）在连续模式下不再需要，只在书首书尾生效（提示「已到开头 / 已读完」）。

## 8. 对轻阅其他功能的影响

（依据子 agent 的 API 依赖排查补充具体改法。）

- **页码**：按槽实测，每个排好的槽都记 `screens = ⌈height / size⌉`，比原来「读到哪章才实测哪章」更早稳定。
- **划线 / 批注 / 搜索高亮**：每个槽有自己的 overlayer，槽加载时绘制该章的标注。
- **听书 / 打字机 / 歌词模式**：它们按「当前章文档」工作；跨章时用 `section-change` 事件切换目标文档，不再依赖 `load`。
- **自动滚动**：单栏滚动是通用的丝滑阅读模式，自动滚动直接在连续容器上按帧匀速推进（`renderer.scrollBy(px)`，速度按「约 N 秒一屏」），跨章不停顿；预载按第 4 节的速度公式提前进行，自动滚动的速度是已知的，可以算得更准。手指按住 / 滚轮暂停、松手继续的现有交互保留；原来「滚到章末 → 调 nextSection → 等加载 → 再继续」的分支在连续模式下删掉。
- **每章加载时挂的监听**（触摸、选区、键盘）：挂在各自的文档上，槽卸载时随 iframe 一起销毁，不需要额外清理。

## 9. 开关与回退

- 排版设置新增「跨章连续滚动」（默认开，随同步）。关掉即回到原来的单章滚动，供排查和兼容旧机器。
- 固定版式（漫画 / 版式 EPUB）、竖排（vertical-rl）书暂不启用，沿用原逻辑。

## 10. 验收

- 本地 Playwright：逐帧触摸拖动 + 惯性，跨 5 章连续滚动，记录每帧 scrollTop。要求：无负向跳变、跨章处没有超过 50ms 的长帧、阅读位置保存 / 恢复正确、改字号后仍停在同一句。
- Surface 实机：系统级触摸注入（InjectTouchInput）快速甩动跨章；横屏滚动模式同测；屏幕键盘弹出 / 收起不跳位置。
- 现有冒烟 e2e、reader-pages、reading-modes 等单测全部通过。

## 11. 渲染器接口契约（fork 与轻阅之间）

fork 仍注册为 `foliate-paginator`（view.js 按名字创建，且运行时会切 `flow`）。翻页模式代码原样不动；只有 `flow="scrolled"` 且元素带 `continuous` 属性时进入多槽模式（轻阅在「跨章连续滚动」开、非固定版式、非竖排时设置该属性）。不带 `continuous` 的滚动模式保持原行为，作为回退。

**主章（primary）**：阅读线所在的槽。下面所有「当前章」语义都指主章。

| 成员 | 连续模式下的含义 |
|------|------------------|
| `continuous`（getter） | 是否处于多槽模式 |
| `start` / `end` / `size` / `viewSize` | 主章内的相对值：`start = scrollTop − 主章槽顶`，`viewSize = 主章高度`，`size = 视口高` |
| `containerPosition` get/set | 同样相对主章（set 时加上主章槽顶）；越出主章范围的值照样生效（连续滚过去） |
| `scrollBy(dx, dy)` | 原始滚动 `scrollTop += dy`（不夹在单章内），供自动滚动按帧推进 |
| `atStart` / `atEnd` | 全书开头 / 结尾（第一个 / 最后一个线性章且到顶 / 到底） |
| `getContents()` | 所有已载槽 `{ index, doc, overlayer }`，**主章排第一** |
| `relocate` | `{ reason, range, index, fraction, size }`：index = 主章，range 只在主章文档内，fraction = 主章内比例。滚动中**节流**派发（约 250ms 一次，取代原来停下 250ms 后才发的防抖），主章切换时立即派发一次 |
| `section-change`（新事件） | 主章切换：`{ index, doc, previous }` |
| `unload`（新事件） | 槽被卸载：`{ index, doc }`（文档随后销毁） |
| `load` | 每个槽的文档创建时一次（含预载），**不代表用户到了这一章** |
| `create-overlayer` | 每个槽一次 |
| `scroll` | 容器滚动时派发 |
| `goTo({ index, anchor })` | 目标章已在槽中 → 滚过去（数字 anchor = 该章内比例），不重新加载、不发 `load`；否则重建槽 |
| `scrollToAnchor(range \| el \| fraction)` | Range / 元素按其所属文档找槽并加上槽偏移；数字 = 主章内比例 |
| `rangeBox(range \| el)` / `scrollToRange(range \| el, opts)` | 阅读焦点用（见 §12「阅读焦点」）：取目标在视口里的位置；把目标首行放到视口顶下 `at` px |
| `next(distance?)` / `prev(distance?)` | 平滑滚动 `distance ?? size`，自然跨章；到已载内容边缘先载邻章再继续；书首书尾返回 |
| `nextSection()` / `prevSection()` | 滚到邻章顶部（必要时先载） |
| `setStyles(css)` | 应用到所有现存槽和以后新载的槽 |
| `heads` / `feet` | 滚动模式下为 null（同原行为） |

轻阅侧相应改动：凡是「找当前显示的文档」一律按 `view.lastLocation.section.current`（或 `getContents()[0]`，连续模式下它就是主章）；打字机 / 歌词 / 词语引导只在**主章**文档上工作，监听 `section-change` 跟随，不再把 `load` 当成「翻到了这一章」；`unload` 时释放挂在该文档上的图层；自动滚动在连续模式下用 `scrollBy` 推进、不再在章末调 `next()`；`crossSectionBySwipe` 在连续模式下不需要。

## 12. 实现说明

渲染器侧已实现（2026-10-07）。同日按 Surface 实机复测做了两轮修订，标为「实机修订」「二次修订」。

- **文件**：`src/vendor/foliate/paginator.js` 是 foliate-js 1.0.1 的 fork，保留 MIT 声明。`vite.config.ts` 里的 `lightread:foliate-paginator-fork` 插件把 view.js 的 `./paginator.js` 和直接写的 `foliate-js/paginator.js` 都指到这个 fork。开发模式要 `optimizeDeps.exclude: ['foliate-js']`，否则预构建产物会绕过插件。构建后 grep `lightread-continuous-paginator`（即 `Paginator.lightreadFork`）可以确认打包的是 fork。原先 `vite.legacy.ts` 对上游 paginator 的三处改写已直接写进 fork。
- **槽**：每个槽就是原来的 View 元素，直接放在 `#container` 里，不另包一层，所以切换模式时可以直接收编现有 iframe，不必重载。载好的 iframe 元素在 DOM 里不再移动，移动会触发重载。
  - 视口上方新载的槽先挂在内容起点之上（`position:absolute; bottom:100%; visibility:hidden`）。那里是负方向溢出，滚不到，也不占布局。排好版后再「提交」进文档流。
  - 视口下方的槽直接追加。
- **占位块（实机修订）**：卸载任何槽都**不写 scrollTop**，而是在原位放一个高度等于该槽最后实测高度的空 div，滚动几何和章序都不变。二次修订起视口下方也一样留占位块，不再直接移除；直接移除会让章序出现空缺。
  - 读者往回接近占位块时，按正常预载规则把该章载进去，新元素先挂在占位块前面、隐藏。
  - 排好的高度与占位块相差不到 0.5px，或者占位块整个在锚点（阅读线）以下：随时换入，看得见的内容不会动。
  - 否则视为「上方高度修正」，只在真空闲时换入并补偿；唯一例外是读者正往上滑、离已载内容顶部不到一屏（紧急）。
- **锚点**：在阅读线处用 `caretRangeFromPoint` 取一个字符的 Range，并记下它在视口里的 y。
  - 滚动事件只做 `y −= Δ`，不触发布局。只有锚点偏离阅读线超过 ¼ 屏，或者主章变了，才重新取。
  - 需要补偿时统一写 `scrollTop = Range 新位置 − y`。这包括：已载槽的 expand（字体、图片晚到）、提交、render、setStyles。scrollTop 被浏览器夹住时也不受影响。
- **真空闲（实机修订）**：同时满足以下四条，才允许改变视口上方的几何（插入、高度修正、高度不同的占位块换入、非可见槽重排样式）和做常规卸载：
  1. 没有手指按着；
  2. 最近一次用户滚动和最近一次 touchend 都已过去 ≥400ms；
  3. 速度估计 ≈ 0（|v| ≤ 0.02 px/ms）；
  4. 连续两帧 rAF 之间，scrollTop 除了我们自己写入的部分没有变化。合成线程的惯性滚动在主线程忙、滚动事件被推迟时也会推动 scrollTop，靠这一条把它拦下。

  每个空闲时段只做一件事：先提交上方待插入的槽，其次重排一个样式过期的槽，最后卸载一个槽。两次卸载至少间隔 1s。只有用户的滚动会推迟空闲计时；我们自己写入的滚动不会（二次修订）——自动滚动每帧调用 `scrollBy`，以前会把计时一直往后推。
- **空闲时的常规卸载（实机修订）**：已载数超过 5 才考虑卸载，每次只挑一个，候选必须满足全部条件：
  - 不是主章，也不是主章前后紧邻的章；
  - 最近 10s 内没有载入过，最近 2s 内没有出现在屏幕上（二次修订：原为 10s，自动滚动时会让槽一路涨到 10 个）；
  - 离视口超过 5 屏（静止时的预载距离 2 屏 + 3 屏）。

  在满足条件的槽里挑最远的一个。
- **上限压力下的卸载（二次修订）**：需要预载、但已载数已到 7 时，先在读者离开的那一侧卸掉最远的一个槽，再载入需要的章。
  - 往下读就卸上方的槽，往上读就卸下方的槽；
  - 候选要离屏幕超过 2 屏，而且不是主章或紧邻的章，不看最近是否用过；
  - 换成占位块后几何不变，所以甩动途中也照样进行，每帧最多一个。

  这样修好了实机上的 7s 停顿：当时已载 10 个槽到了硬上限，连续甩动又一直等不到真空闲，下一章载不进来。
- **预载上限**：非紧急预载最多到 7 个已载槽，紧急（剩余不足一屏）在压力卸载找不到候选时最多到 10 个。卡在上限时每 250ms 重试一次；手指按下时也会检查一次，因为在已载内容末尾滑动不会产生 scroll 事件。
- **与 §4–§11 的偏差**：
  1. 向上预载的阈值改为 `max(2×size, v↑×T×2)`。§4 写的是 1×size，但它和「紧急」阈值相同，结果所有上方插入都会发生在甩动途中。现在提前载入，等真空闲再插入；只有 D↑ ≤ size 而且正往上滑时才立即插入。
  2. §5 的「150ms 无滚动」改为上面的真空闲判定（400ms + 速度 ≈ 0 + 两帧 scrollTop 不动），只约束改变上方几何的操作。卸载一律换成占位块，不做 scrollTop 补偿；上限压力下可以在甩动中进行。槽数上限改为上面的规则（软 5 / 预载 7 / 硬 10），§5 的「超长章只保留前后各 1 个」不再单独实现。
  3. `relocate.detail` 不带 `size`，和原来的滚动模式一致；带上会改变 view.js 的进度计算。`fraction` 夹在 [0, 1] 之间。`next()/prev()` 结束时 `reason` 为 `'page'`（原来的滚动模式是 null）。
  4. `section-change.detail.previous` 是上一个主章的序号，没有时为 null。
  5. 极短章（高度不到阅读线的 20%）：`goTo` / `scrollToAnchor` 之后，把目标章「钉」成主章，直到用户自己滚动。否则一跳过去，主章就落到了下一章。
  6. `render()`（容器尺寸变化，或 margin / gap 等属性变化）会同步重排所有已载入的槽。`setStyles` 按 §6 处理：先排主章和可见的槽，其余在真空闲时逐个排。样式内容没变时不重写样式表。
  7. 没有做下下章的提前解压（§4 最后一条）。
  8. 竖排：任何一个槽检测到 vertical 书写方向，就退出连续模式。保留主章，回到原来的单章行为；这本书之后不再进入连续模式（`open()` 时重置）。

- **阅读焦点（2026-10-07）**：程序替读者把视图移到一段文字时（听书跟随、搜索结果、划线、点睛、回到朗读位置）不再顶端对齐，规则在 `src/services/readingFocus.ts`（舒适区 25%–65%、焦点线 38%，按扣掉显示中顶栏 / 底栏的可读区算；单测 `npm run test:reading-focus`），渲染器只管几何：
  - `rangeBox(range | el)` → `{ top, bottom, viewport }`：目标首行顶 / 末行底相对滚动视口顶边的 px。任一已提交的槽都行，非连续的滚动模式也可用；翻页、竖排或目标不在显示中的文档时返回 null。
  - `scrollToRange(range | el, { at, behavior: 'smooth' | 'auto', duration, reason })`：把首行放到视口顶下 `at` px（默认一个 margin，同 `scrollToAnchor`）。`smooth` 用可让位的动画：读者滚轮 / 手指一动就停；新的调用取消还在跑的旧调用。连续模式下目标所在槽成为主章（钉住到用户滚动），`#cAnchor` 记的是它此刻在屏上的位置，重排后仍停在那里；单章滚动模式下 `render()` 重新锚定时也保持 `at`。翻页 / 竖排等同 `scrollToAnchor`。
  - `goTo({ index, anchor, focus: { at, behavior } })`：Range / 元素锚点落在 `at` 处（`behavior: 'auto'` 不做动画），数字锚点（章首、比例）不受影响。轻阅用 `view.resolveNavigation()` 解析 CFI 后直接调渲染器的 `goTo`，再自行 `history.pushState`。
  - `scrollToAnchor` 不变（顶端对齐），目录 / 章节跳转、书签、续读、「回到第 N 页」继续用它：它们存的是当时屏幕顶上那一行，挪到焦点线会让每次打开的位置往前退一截。
- **已知限制**：
  - headless 下 iframe 加载快、合成线程惯性的行为也和 WebView2 不同，Surface 上的大幅回跳在本地没有复现。修订的依据是 Surface 日志（每次回跳之前都是甩动中的一批上方卸载），仍需实机复测。
  - 如果读者两侧 2 屏以内堆满了极短的章，压力卸载找不到候选，紧急载入最多可到 10 个槽。
  - 往上甩得比预载快时，会短暂看到占位块的空白。
  - D↑ ≤ size 时的紧急插入仍会在甩动中写 scrollTop。
  - 横屏测试必须把轻阅设置切到「滚动」，不能只强制渲染器的 `flow`，否则轻阅会把竖向滑动当翻页并调用 `next()`。
