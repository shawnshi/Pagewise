## 修复内容

原测试调度器在 UI 回调结算之前选择窗口。恢复弹窗已 dismiss、但生产 `onDismiss` 尚未把当前窗口指回保留输入时，测试可能选中 Activity 根窗口，再等待一个不会获得焦点的窗口。旧 Android 超时回执保留，不能据此单独判定生产代码故障。

新调度顺序：

1. 排空此前主线程回调，等待两帧，再读取当前存活窗口；不跨异步边界缓存窗口身份。
2. 订阅焦点、布局与挂载变化。信号到来时重新结算、重新取样；窗口替换或移除后解除旧订阅。
3. 必须同时满足已挂载、已布局、无待布局请求和拥有焦点，才运行原测试动作。
4. 每项只有一个固定 **8 秒**截止时间；窗口切换不续期，不按帧轮询。成功、失败或取消均移除观察器、帧回调和超时任务；终态只交付一次。
5. 不接管生产弹窗的 `onDismiss`，不修改生产代码，也不删除原来的触控、完整页脚、CAS、未决结果和不重放断言。

文件：

- `reader/scripts/fixtures/NativeWindowReadyGate.kt`：测试专用就绪门。
- `reader/scripts/fixtures/NativeStatsSettingsMain.kt`：Android 生命周期适配及取消清理。
- `reader/scripts/fixtures/NativeWindowReadyGateMain.kt`、`reader/scripts/test-native-window-ready.mjs`：宿主回归。
