# Pagewise 全量审计与修复记录（2026-10-18）

> 后续状态：2026-10-19 已按用户明确授权构建、签名并安装 Release 1.0.0（正式包名 `io.pagewise.reader`）。当前产物/安装证据见 [部署记录](deployment.md) 与 [验证状态](validation-status.md)。本文设备表格仍是历史 Debug 合成验收，不外推为本 Release 全量验收；完整原生听书队列已实现，最终息屏长听与故障恢复仍待补验。

本记录是一次面向文石 Note X3 Pro / Android WebView 的架构、业务流程、响应性能、稳定性与易用性审计。
审计分两轮：先由三个独立只读审计（阅读内核、书库与扫描、墨水屏前端）给出证据，再由主代理逐条核对源码、
筛选可复现项并实施最小修复；后半程在已连接的目标机上安装、操作并采样内存与崩溃日志。
主机与浏览器检查、设备实测分别记录；“通过”不自动等同于物理残影/触控手感/长时间稳定性或耗电验收。

- 基线：`baa1d76` + 工作区中已有的伴读/阅读助手未提交改动（全部保留，未覆盖）。
- 修改前的目标文件备份：`.cache/audit-20261018/baseline/`（本地，不入库）。
- 范围：`reader/` 前端、Android 原生插件、SQLite 存储层、Vue/Vite 构建与 host 测试。未触及 relay 服务端逻辑。

## 1. 结论摘要

- 整体分层清楚：SAF 只读目录 + SQLite 索引、foliate/MuPDF/PDFium 双引擎、会话与草稿服务、统一设置与排版解析。
  扫描的“不完整枚举不得判定文件消失”、临时查阅不污染主进度、草稿容量拒绝而非静默淘汰等约束是有意的保护，不应按普通 bug 移除。
- 未发现初始源码中的 P0；设备实测随后发现一个可必现的 P0：40 MB 源文件经 base64 传输时 OOM 杀进程，
  已用原生临时文件 + 二进制读取修复。其余优先项是**进度尾写丢失**、**大文件传输解码成本**、**PDF 渲染跨卸载/像素预算**、
  **书库/在读页的可见性缺陷**与**删除/改名顺序的数据安全**。
- 三个审计报告中的部分结论经复核不成立，已剔除：阅读面板的 `--safe-top` 在 `.reader` 作用域内有定义；
  `.pagewise-eink *` 已统一关闭动画/阴影/模糊；排版面板在 `pointer: coarse` 下已是 44px 触控目标；
  “完整枚举 + 单书解析失败不标记缺失”是现有测试明确保护的安全取舍。

## 4. 未修复的残余风险（按优先级）

1. **导出仍受单本书内存约束**：流式 zip 已避免同时持有全部书字节与完整包，但每本书仍需一次性计算 SHA-256（源文件上限 64 MB）；超大单文件需要增量哈希或原生校验。
2. **书库查询与索引**：`listBooks` 全量读取、`ORDER BY added_at` 无索引、每页仍全量过滤/排序后再切片。
   设备上 4000 本可正常启动/渲染/搜索（PSS 228–244 MB，冷启动 901 ms），但尚未采集单次查询长任务和更大库的耗时；需要时再决定 SQL 分页或索引。
3. **EPUB relocate 的 O(N+M+T) 统计与页脚 DOM 重建**：属于每页成本，需在目标机采集长任务后再优化，避免破坏分页语义。
4. **PDF 双引擎整文件副本**：MuPDF 失败回退时未立即释放已取得的文档/字节；40 MB PDF 实测可开，但并发副本仍值得后续收敛。
5. **桌面目录扫描错误语义**：若未来重新启用桌面导入，必须先补结构化错误与 `truncated`，不能把读失败当空目录。
6. **12 MP 像素预算的清晰度取舍**：400% 倍率下文字会比原生 DPR 略软；如后续设备内存允许，可改为按设备内存分级预算，而不是固定值。

## 7. 仍未验证

- 系统级 SAF 撤权/重授权：本机 `adb shell cmd uri_grants` 返回 “No shell command implementation”，`pm`/`am` 也没有撤销已持久化 tree grant 的接口，未 root 无法在不丢数据的前提下制造真实撤权；`permission-denied` 分支仍由 host 测试覆盖，`pm clear`（授权不存在）与重新选目录/扫描已验证。
