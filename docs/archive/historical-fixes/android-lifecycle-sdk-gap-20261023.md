## 已核实的缺口

Tauri Android 2.11.5 的 `PluginManager.onActivityCreate` 只在第一次调用时登记 Activity 和三个 ActivityResult 启动器，后续 Activity 直接返回。启动器和结果回调槽是 SDK 私有状态，没有公开的重置入口。

`PluginManager.load` 可以替换同名插件，但不会重新注册启动器或处理旧回调。因此不能简单更新 Activity 引用、换一个页面 host 就声称修复完成。项目的导入、导出及字体选择等路径仍使用这条 SDK 结果链。

公开 API 核验与独立架构核验结论一致。独立核验因工具预算到达而止于**部分静态检查**：它证明了现有 SDK 的重置能力缺口，不证明所有替代方案都不可能，也不是补丁通过或运行验收。

## 建议追加批准的最小范围

允许在**项目内**维护一个锁定 Tauri 2.11.5 的 Android 生命周期兼容补丁，并做必要的项目插件重绑定：

- 不升级依赖版本，不写全局 SDK／Cargo 缓存，不改数据库和持久化格式，不新增第二套 canonical 状态或恢复管线。
- 补丁原件与上游源码哈希绑定，保留许可；通过现有构建准备入口应用，源码不匹配则停止构建，不能静默使用错误版本。
- 为新 Activity 正确登记启动器和插件实例；按身份／代次解绑，旧销毁通知不得关闭新宿主。
- 旧结果不得误投新请求；同类并发不能覆盖单回调槽。是否承接重建前已打开的选择器，必须先确定合同，不能默认为把旧回执交给新会话。
- 已接受的长期任务与不确定写入继续走原有核对机制，不自动重放、不以 UI 销毁标记取消成功。
- 先做隔离切片及定向失败控制，再独立复审和 API 32 实测；不能保证这些边界时停止，不扩大修改。

这项追加授权不包含主设备安装、推送、发布、私有书库读取或额外依赖升级。
