# 知页阅读器 · Pagewise：实施方案与阶段验收

> 历史快照：本文件保留当时的计划或执行记录，不作为当前功能、验收状态或安装指令。当前实现以[项目说明](../readme.md)、[验证状态](validation-status.md)和[设备准入](device-admission.md)为准。

## 1. 当前目标与范围

面向 BOOX Note X3 Pro，维护一个 Android 个人本地阅读器，承载 4000+ 本书的书库。源码基于 LightRead v1.15.0 / `9027e9a09ef19c1c37cc828c9fd42b21119e1ac9`，位于 `reader/`，工作分支仍为 `pagewise/epub-first`。版本保持 `1.15.0`，包标识保持 `io.pagewise.reader[.debug]`。

本方案依据根目录《LightRead_NoteX3Pro_开发评估与功能规划.md》与实际源码重新排序。原规划引用的 `cd53268f9aa5891c4eb8d73f6126ac6570d12dea` 不是当前代码基线；其中性能、识别率及工期是目标或估算，不是当前实现证据。原规划与 UI 规范保持只读。

**本轮需求替代早期“仅离线 EPUB、移除 INTERNET”的原型范围。** 当前保留 EPUB、MOBI、PDF、TXT、Markdown，保留普通 AI/翻译及系统/Edge 听书，因此保留通用 HTTP 和 Android INTERNET 权限。本地书库不依赖账号或云同步；本地优先不等于已经证明零外联。自动网络行为须另行核验。

移除且不再排入后续路线：桌面/PWA/iOS 发行、歌词模式、BabelDOC、在线书源、Calibre、账号与同步、设备互传、应用内更新、论文 CLI Agent。不得根据旧规划把它们作为“可选功能”重新接回。

保留：普通阅读与排版、进度、批注、书签、本地书单/标签/置顶、阅读统计、归档交换、普通 AI/翻译与系统/Edge 听书。AZW/AZW3、FB2/FBZ、CBZ/CBR、DjVu、独立 HTML/HTM/XHTML 不再提供导入或打开入口。EPUB 内部 XHTML 及 TXT/Markdown 转换所需 HTML 不属于退役对象。

## 2. 对原方案的关键修订

| 实际证据 | 设计决定 |
|---|---|
| `library.refresh()` 原先读取全量元数据后逐本预载封面；store 和 adapter 都持有 URL | 首先停止全库预载并统一封面所有权，不以 `loading="lazy"` 代替资源治理 |
| Android `listBooks()` 查询元数据，原书字节另存；Dexie 的记录读取形态不同 | 首期保留全量元数据缓存；不因 4000 本就先迁移 SQL schema；浏览器数据不代表 SQLite 性能 |
| 搜索、标签、书单与置顶共同决定可见集合 | 全集合筛选、排序后再分页；保持书单范围、置顶优先及中文排序；单独标明“选择本页”和“选择全部匹配项” |
| 旧类型/归档允许已退役格式 | 保留被动数据兼容，关闭新导入和解码入口；不删除旧记录或原文件，也不谎报可阅读 |
| `TypographyPanel` 与阅读器共同使用全局 `settings.reader` | 单书排版必须经有效设置解析器生成，不能进书时覆盖全局、离书时猜测恢复 |
| EPUB 位置保存使用 600 ms debounce | 不能据此承诺休眠、后台或进程终止时不丢位置；需要独立生命周期落盘链路 |
| 当前手机目录选择受限；没有目标机验收 | SAF、文件提供器、刷新和进程恢复单独设门，不以浏览器截图冒充完成 |

不要把书库查询、文件导入、语言判断、排版及厂商刷新绑定成一次大重构。它们的失败条件、数据所有权和验收设备不同。

## 3. 目标数据流与资源合同

```text
本地存储 → 全量书目元数据 → 搜索/标签/格式/语言/书单 → 置顶与排序 → 分页 → 当前页卡片
                                                    当前页 IDs / 可见统计缩略图 → 同一个应用级封面池 → 图片 URL
书籍元数据 + 语言建议 + 全局默认 + 单书覆盖 → 有效排版 → 阅读器
内容位置 → 保存调度器 → 本地存储 → 重开定位
```

### 书库与封面

- 默认每页 12 本，当前 UI 只允许 12/24；变化筛选时重置页码，删除/导入后校正越界页。
- 元数据查询不得改动原数组、推断人工已读状态，或加载原书字节。阅读进度不等同于“已读”。
- 首期封面池上限 32 项、并发 2 项。这是初始工程策略，不是 Note X3 Pro 最优值或内存实测值。
- adapter 每次返回独占的新 URL，不再维护第二份 URL 缓存。书库池管理自身 URL 的引用、淘汰及撤销；导出/转换等独立调用方在 `finally` 释放自己的 URL。
- 换页、切换范围及离开页面必须释放 lease；迟到结果不能写入新页面。不能撤销仍被引用的 URL。统计缩略图只在可见时借用同一池，不能依赖已经卸载书库页的 URL；应用退出才销毁共享池。
- 没有封面与读取失败必须分开。失败可展示错误，不得吞成“无封面”或触发无限重试。

`refresh()` 仍可能自动关联书单待找条目，不是对真实书库的纯只读基准。所有测试使用合成数据和独立浏览器存储。

### 元数据与排版

下一阶段优先保留“值、来源、置信度/确定性、用户覆盖”之间的区别。标题/作者优先用文件内元数据，文件名解析只作缺失项建议；不自动批量改名、移动或写回原书。

语言策略按“单书手动选择 → 可靠声明 → 本地文本判断 → 未知/混合”执行。混合语言不能为了凑识别率强归中文或英文；体裁标签不进入确定性语言规则。

有效排版通过纯函数计算：

```text
全局默认 → 对应语言配置 → 单书显式覆盖 → 当前显示模式约束
```

原始全局设置不随进出书改变。单书清除覆盖后回到语言配置；混合/未知使用明确回退。现有大字/墨水屏等预设层需与新解析器对齐，不能再形成互相覆盖的两套状态。字体先核对设备实际可用性，再确定中西文 fallback；原文中的字号、行距与设备阅读器单位不能直接当作 CSS px。

| S2 元数据与本地导入 | 来源与覆盖规则；可取消/可重入导入任务；错误分账；元数据编辑 | 未实施 | 合成异常文件/重复项/取消/空间不足；不覆盖人工元数据，不修改原文件 |
| S3 语言与排版 | 本地语言建议、四类回退、有效设置解析器、单书覆盖、中文排版细节 | 未实施 | 中/英/混合/未知样章；手动优先；无全局污染；换字体/重排后位置可恢复 |
| S4 目标机文件与保存 | SAF 目录授权、授权撤销、URI/file provider、本地保存与导出恢复 | 未实施，真机门未通过 | 实机读取、休眠重开、异常中断、真实导出恢复及失败反馈 |
| S5 墨水屏交互与刷新 | 列表优先布局、黑白层次、少动画、触控目标；必要时接官方厂商能力 | 未实施完整适配 | 目标机触控/残影/刷新/续航证据；不靠 UA 或 CSS 声称硬件适配 |
| S6 证据定位的普通 AI | 手动触发、受限上下文、引用回链到 CFI/页码、成本与取消 | 保留原普通能力，增量未实施 | 来源能回到原文；不扫描/上传全库；无 CLI Agent 或 BabelDOC 回流 |

S0/S1 不改 SQL/Dexie schema。只有真机基线证明全量元数据缓存、描述字段或查询延迟成为瓶颈，才评估数据库分页、投影或索引。新 schema 必须另立恢复点和数据对账，不能由性能测试结果自动获得迁移权限。

阶段以可运行、可使用的纵向切片交付，不承诺原文估算的固定周数。无设备时可以推进独立源码工作，但 S4/S5 及设备性能不能变成“已完成”。

## 5. 故障与验收矩阵

| 故障/边界 | 必须观察的行为 |
|---|---|
| 空书库、搜索无匹配、页码超界 | 正确空态与总数；页码有效；不是读取错误的伪空态 |
| 多标签与书单/格式/语言交叉 | 先筛选排序再分页；页间无漏项/重复；置顶顺序稳定 |
| 连续快速换页、迟到封面、载入失败 | 引用/并发/容量受限；旧请求不能覆盖新条目；错误可见 |
| 历史退役格式及旧归档 | 保留记录和原字节，可识别/导出；导入打开守卫有效；正常 EPUB 内部 XHTML 不受伤 |
| 旧歌词设置与多层预设快照 | 仅退役歌词层；未手调的值恢复；人工调整与其他预设恢复链保留 |
| 损坏原书/归档、部分导入、取消、空间不足 | 逐项结果可对账；失败不报成功；不默默覆盖旧书/批注 |
| SAF 授权失效、外置存储不可用 | 区分失权、缺文件与读取错误；允许用户重新授权，不清库 |
| 后台、休眠、屏幕旋转、重排、杀进程 | 已确认落盘的位置可恢复；无法保证的终止窗口明确报告 |
| 联网不可用、普通 AI/TTS 失败 | 本地阅读继续；请求失败可见并可取消；不恢复账号/书源依赖 |

性能验收采用设备上的冷启动、筛选/换页、书籍打开/翻页、内存峰值和长时资源曲线。先记录设备、WebView、APK 哈希、书库规模与样本大小，再固定可重复口径。主机 4000 条合成数据的用时只能标为主机微基准；原规划中的数值先列为待校准目标，不能替代目标机数据。

## 7. 数据保护、协作与恢复

- 不访问或扫描真实 4000+ 本藏书，不批量重命名、移动、清库或卸载；不删除远端账号、同步数据、发行包，不部署/发布。
- 旧格式、书源等元数据和数据库命名可为历史归档被动保留；保留数据不等于保留网络运行入口。不能为“删得干净”丢弃书籍、进度、批注或统计身份。
- 原书与数据库不属于源码回滚范围。未来新版本导入的数据，不能靠回退 Git 自动撤销。升级前需要用户授权的归档与实际恢复演练。
