# 阅读助手提示词与完成度合同

## 输入与证据边界

- EPUB／文本普通问答只发送实际可见 Range 的文字，不回退读取整章正文；选文解读和概念展开分别使用用户选文与所在段落。正文上限 6000 字符，选文入口保留原有 1500 字符限制，概念段落保留 600 字符限制。
- 问题上限 1200 字符，历史只保留最近 4 轮完整问答；每条历史消息的序列化内容不超过 4000 字符。失败、停止和空回答不进入后续历史。缺少可见正文时明确标为 unavailable，不假装有章节依据。
- 书名、作者、章节、正文、概念简释和历史回答都是数据，不拼入系统规则。原文、模型派生解释、未核验背景应区别对待；禁止编造引文、出处、页码、联网核验经历或未提供的后续情节。
- PDF 助手及 PDF 选文解读使用同一个 PDF 消息构造器，只提供显式页码与有界文字，不发送整份 PDF、其他页、图像或用户笔记。选择入口使用选文所属页，而非滚动后页眉所在页。

这些规则是模型约束与客户端边界，不是事实正确或完全抵抗提示注入的保证；背景与引文仍需核验。

## 点睛阅读

客户端自有密钥通道和 relay 源码共用 `reader/src/services/dianjing/prompt.ts`。模式仍为 mark、summary、translate，现有 HTTP 请求字段与 NDJSON 类型不变，temperature/max_tokens 不变；版本元数据与响应头为增量扩展。输入元数据、编号正文和已知术语改为用户 JSON 数据。

- mark 在体裁未知时先遵守防剧透；体裁判断仅在完整有效的请求之后采纳。每块显式指定最多 12 个均匀分布的段号生成必需段意，其余要句／术语／注释仍可依据整块已提供正文。段意采样本身不增加请求，也不要求密集短段在固定 1500-token 预算内生成数百行。分块同时计入编号后的 3000 字符输入上限，密集短段可能因此拆成更多请求；完整句子与原位置映射不丢失。单个句子仍放不下时在联网前报错，不截断正文。必需段号与完成度校验来自同一个实际发送计划。可选标记宁缺毋滥，未核验背景必须注明。
- summary 基于派生段意与选出的原句，不等于完整章节原文。来源先预算、再编号，保留前后分布，避免最后截断导致编号指向未发送的句子。输出一条 sum 和 0–3 条有依据的 pt；没有编号要句时只输出 sum。无效／重复编号、超过 3 点或缺少 sum 不写入要义缓存。
- translate 忠实翻译输入句子，不补写、不续写、不自行消歧，保留句号编号。当前单句卡片要求一个对应编号的译文。断流或格式失败后可以保留部分内容，但必须显示未完成，允许重试；不能因 text 非空就算成功。
- 脉络和速读复用当前版本的结果，不另发独立提示词；基础词色仍为离线处理。

## 完成、缓存与版本

SSE 需要 `[DONE]` 或正常 `finish_reason=stop`；length／content_filter、没有完成信号的 EOF、坏 JSON、下游失败均视为失败。整段 JSON 响应保留兼容，但明确的非 stop finish_reason 仍为失败。停止不会自动重试或切换模型。

点睛结果只有在结束有效、必需段意及请求的体裁信息通过校验后才写 `complete:true`。这是传输与格式完成，不证明模型没有漏掉语义细节或生成事实错误。relay 中途失败必须终止下游流，不能正常 close 冒充成功；已产生的文本仍计入用量估算。

内置通道先读取不带正文、设备标识或密钥的 `/models` 版本元数据。版本缺失或不匹配时不发送正文 POST；随后还必须核对实际 NDJSON 响应的 `x-dj-prompt-version`。两次核对均匹配 `dj3` 才采用结果，响应头来自服务端实际模块常量，不回显客户端自报值。版本失败清空等待队列，明确提示服务端需升级，不自动改配置、切换模型或降级；自有通道不受内置服务版本门影响。

`PROMPT_VERSION=dj3`，不把 dj1/dj2 或未经版本确认的旧 relay 自动分析当作新合同结果。旧缓存不删除，书签、用户批注、采纳／忽略反馈及持久化格式不变。启用智能分析时未命中新版本缓存可能重新请求；回滚源码版本可重新选择旧缓存命名空间。

## 发布与验证

APK 仅更新客户端。内置点睛由 relay 端拼装提示词；服务端需另行授权、同步发布；旧服务未提供版本证明时，新客户端明确拒绝该内置通道。不能把客户端安装成功当成服务端提示词已更新。本轮不部署 relay，不改用户模型配置，不调用真实模型。

本轮验证应包含纯消息构造、转义后的长度预算、摘要采样／编号、完整与截断流、真实 ReaderView／点睛缓存／卡片合成浏览器路径、官方构建、独立审查及当前源码 APK 的保留数据安装。测试成功不代表真实模型效果、远端服务可用性、物理墨水屏体验或一般用户准入。
