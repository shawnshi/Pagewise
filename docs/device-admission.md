# Android 设备与安装包准入

本页描述当前 Pagewise 的检查边界。开发、构建成功或元数据检查通过，均不代表可覆盖原有应用或已完成真实设备验收。当前验证范围见 [验证状态](validation-status.md)，使用与构建入口见 [项目说明](../readme.md)。

## 1. 先确定目标身份

区分以下应用，不用“知页”显示名代替包身份：

- `io.pagewise.reader`：正式身份，尚未正式发行。
- `io.pagewise.reader.debug`：常规开发调试身份。
- `io.pagewise.reader.acceptance.v03.debug`：当前独立合成验收身份，不覆盖原应用，也不恢复原应用数据。

操作前核对包名、UID、签名证书、实际 APK 哈希及目标设备。输入或截图前再核对当前前台归属。设备序列号只在必要进程参数中使用，不写入报告或版本库。

已有包、签名不同、身份未知或来源不符时，停止安装。没有目标包不等于获得新装许可；不要通过卸载、清数据、改包名或换用原应用绕过边界。

## 2. 安装包静态检查

在安装前核对：

- ARM64 ABI、minSdk/targetSdk 与目标设备兼容性。
- 包名、启动 Activity、调试状态、签名及预期哈希。
- 权限清单、备份恢复策略和共享 UID。独立合成验收包禁用备份恢复，不使用共享 UID。
- 打包的原生库是否对应当前前端资源与原生模板，避免把旧资源误当作新功能。

当前应用保留可选网络服务，申请 `INTERNET`。早期“Pagewise 必须完全不申请网络权限”的离线原型要求已不适用于当前产品；不能为通过旧规则而改写检查结果。

`scripts/Test-ReaderApk.ps1` 的早期离线模式及原型文件是历史基线，不是当前安装包的独立通行证。`scripts/Test-NoteX3Pro.ps1` 可提供只读设备元数据，但不证明阅读、保存、返回或授权行为通过。

## 3. 数据与目录授权

合成验收应使用独立应用身份和专用合成目录：

- 首次检查空库、未配置目录与取消选择的行为；目录选择只能授权指定的合成目录。
- 正式读写或截图前检查是否出现非夹具数据。若出现，停止该分支；不读取或输出书名、正文、笔记，不清库、不卸载。
- 不枚举或截图系统选择器中的个人文件列表。目录选择由用户完成，不能静默扩大授权范围。
- 监测目录只读；应用不修改或删除源文件。若测试需要新增/移除夹具，只处理本轮创建且哈希仍匹配的文件，并保留恢复内容。
- 持久化目录授权是设备本地状态；归档或换机不能自动继承另一台设备的授权。

## 4. 更新与验收

对已明确授权的同身份更新，先确认签名兼容、旧包和恢复点、现有数据边界及没有待保护的编辑输入。使用保留数据的更新方式，更新后重新核对 UID、实际 APK、夹具记录和笔记；不得把“安装成功”当作数据或功能验证。

最薄实机路径至少区分：目录授权/取消、实际源文件读取、书库显示、阅读渲染、进程重启后恢复、原生 Back 和保存结果。物理墨水屏显示、人工触控、长时间稳定性及耗电需另行记录。

本地检查仅作为记录，不写入未经确认的设备“PASS”状态。不要修改全局字体、刷新率、冻结策略或其他设备设置来获得表面通过；认证失败、目标不符或验证预算耗尽时保留证据并停止。
