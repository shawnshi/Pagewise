# 自动排版与单书显示方案：分析及实施计划

适用范围：流式 EPUB 及阅读时转为 EPUB 的 TXT、Markdown。保留当前菜单、图标及功能移除改动。本计划不修改原始《Pagewise_中英文阅读排版方案.md》。

## 1. 对原方案的判断

原方案的单位区分、中英文段落差异、按书覆盖及字体完成后重定位原则可直接采用，但第八节所述基线已有变化：当前代码已经提供段距、缩进、语言覆盖表、单书覆盖表及草稿事务，不需要重建一套设置系统。

本次源码核对发现：

- `settings.ts` 的语言默认字号、行距等被全局 `reader` 值覆盖，导致语言方案名义存在、实际不完整生效。
- `ReaderView.vue` 只用数据库元数据中的 `language`；实际 EPUB 的声明、章节语言及正文证据尚未可靠进入解析器。缺失语言不能当作英文，也不能按界面语言猜书籍语言。
- 排版面板的文字参数按书保存，但主题、翻页、分栏等 `readerPatch` 仍回写全局；“仅本书”的边界需要修正。
- 恢复自动预览重复拼装默认值，可能与实际开书解析分叉。
- 首次打开没有完整等待自定义字体注册、字体加载及重新分页；当前页码缓存签名也未覆盖全部排版参数。

原方案给出的物理 pt 是设计建议，不是经过本机尺量验证的结果。CSS px、设备像素及真实毫米分别处理；未标定时保留现有基础字号，不把其标为真实 12.5 pt。不承诺所有用户都获得主观最优效果。

## 2. 解析与保存合同

### 默认与优先级

顺序为：内置自动方案 → 用户本语言默认 → 当前书的显式配置。仅打开书籍不写入单书表，也不把自动默认伪装成手动快照。

自动方案按原文参数表实现（不是舒适度实测结论）：

- 中文：行高 1.70、首行缩进 2 em、常规段距 0.15 em、约 32 个全角字的目标行宽。
- 英文：行高 1.55、普通段落缩进 1.2 em、首段及标题后段不缩进、左对齐、约 65 ch 的目标行宽。
- 混排：中文行高 1.75、缩进 0、段距 0.45 em、约 32 个全角字的目标行宽；独立英文段落按中文字号的 0.96 倍及行高 1.55 处理，并标记语言与断词规则。

字号未标定时继承现有基础字号；尺量校准后，中文自动方案按约 12.5、英文约 12 物理 pt 换算为 CSS px。用户保存的单书字号继续具有更高优先级。本次不实现 mm 页边距、独立标题/脚注字号体系或完整多字体包；这些原文建议仍需后续布局与字体供应工作。字体使用设备可用衬线字体及明确回退链，不在本次引入字体下载依赖，也不声称未打包的思源宋体或 Literata 必然存在。

面板显示推断的语言、方案及设置来源，并允许显式选中文、英文、混排模板纠正自动判断。

### 语言与保护边界

最多抽取三个分散的线性章节，限制正文抽样长度；不全书扫描、不联网、不改写正文文本。依据有效元数据、章节语言及有界正文统计判断。声明与多章正文强烈矛盾时记录冲突；短引文、单篇序言不能轻易改变整书策略。TXT、Markdown 临时 EPUB 的默认语言不能被误当作可靠原书声明。

只调整样式、语言属性和段落语义标记；优化模式临时移除普通正文中冲突的内联文字样式，切回原版或失败回滚时恢复，不修改源文件。不插入字符或改变段落结构，保护 CFI、批注与搜索。引文、列表、表格、代码和诗歌不被普通段落规则一刀切处理。PDF、固定版式及竖排不强套流式正文方案，保留原有专用链路。

### 单书记忆范围

“仅本书”只保存相对开面板时实际有效方案发生变化的字段，不把未修改的自动默认冻结为自定义；已有旧快照继续兼容。范围包括字体、字号、行距、字距、缩进、段距、对齐、目标行宽、显示模式，以及主题、翻页/滚动、连续滚动、分栏、竖屏策略和进度显示。改 A 书不能改变 B 书的上述配置。

护眼调暗仍属当前设备偏好，界面明确标注为全局；不混入单书文字方案。应用到本语言默认是显式选择，不能覆盖其他书已有的单书配置。

取消不保存。恢复自动只在成功应用后移除当前书的覆盖，不删除其他书或本语言默认。任何控件在恢复预览后再次编辑，都应取消“仅移除覆盖”的标志，防止用户修改被忽略。

## 3. 设备校准

提供固定 CSS 长度的参考线。用户用尺量实际毫米数后计算 `CSS px/mm = 参考线实际 CSS 宽度 / 输入毫米数`，再换算目标物理字号。校准记录只保存在本设备，不新增云同步；DPR 改变后提示重新标定，自动字号退回安全基线。

合成测试可以验证校准计算、输入边界及清除流程，但不能当作真实尺量。交付时单独说明本机是否进行了人工测量。

## 4. 应用与失败语义

开书：读取书 → 判定上下文 → 解析有效方案 → 注入样式及字体 → 初始化原位置 → 等待字体与布局 → 恢复 CFI → 显示正文。异步结果不得落到已离开的书籍。

手动应用：保留真实锚点与原配置 → 本地待应用状态 → 字体/分页完成 → 验证导航成功 → 先持久化再确认。写入失败、字体失败、导航失败或上下文失效均不得提交；保留草稿并回退正文。开书遇到不可用自定义字体可明确临时回退，不能悄悄改写原单书配置。

页码测量缓存包含语言/方案、显示模式、字号、行距、字距、段距、缩进、行宽及字体标识，避免跨方案复用旧结果。

## 5. 分步实施与验收

1. 冻结当前脏工作树和现有排版测试基线，建立可恢复备份。
2. 补齐纯函数：方案、语言上下文、校准、配置校验及覆盖优先级；保持旧单书覆盖兼容。
3. 接入开书和草稿事务，修正单书版式边界、恢复自动、字体等待、布局及缓存。
4. 更新界面提示、校准入口及中英文文案；补齐真实 Vue/浏览器测试，不以手写流程模拟代替真实提交。
5. 由未参与生成的独立审查者核对实际 Diff、原需求和测试证据；修复有效问题。
6. 使用现有离线 Android 工具链重新嵌入前端并生成签名验收 APK；检查包名、证书、权限、ABI、原生库及前端绑定。
7. 在既有 NoteX3Pro 独立验收包中，只使用原有及任务新建的中英文合成夹具；验证自动选择、单书修改、跨书隔离、重开、进程重启、恢复自动及原数据保留。不得卸载、清数据、读取真实书库或声称未做的光学/听感验证。

关键负向用例包括：未知/错误语言、序言干扰、混排、无效数值、未标定/失效标定、固定版式/竖排、缺失字体、持久化失败、导航失败、取消、恢复后再编辑、快速切书及已有语言/单书覆盖的兼容。
