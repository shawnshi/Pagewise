# 三个图书推荐功能：设计决策与实施合同

## 文档分析与取舍

依据用户指定的 `C:/Users/shich/Downloads/book_recommendation_design_doc.md`，实现三个入口：正在阅读页“推荐”、书籍详情第四个“相关与拓展”标签、真正到达书末后的四本相关书弹窗。只推荐当前书库中实际存在的记录。

原 PRD 的目标成立，但以下条款不能直接作为正确性承诺：

1. “至少3本”与小书库／低质量信息下“宁缺毋滥”冲突。采用后者：显示真实数量，可为0，不用弱关联凑数。
2. 0.78、0.52–0.74 等余弦区间依赖具体向量模型和语料，没有本地标定依据。首版采用可解释规则和本地稀疏 TF-IDF 词项向量；它不是 BGE 语义嵌入，不安装模型或向量数据库，不把其分值冒充语义置信度。
3. 当前分类只有已验证主类别和主题等字段，没有可靠的子分类树、丛书 ID、引用关系或“代表作”标记。不虚构这些属性。多样性使用已知类别／主题；仅对同题名同作者记录及明确题名分卷做保守折叠，标明记录／分卷数，不推断缺失卷次。
4. 原作者、标签、简介不足以证明“反驳、引用、互为续作”。理由先写可核对的共同作者、分类、主题／词项事实；可选 AI 理由标记未核验，不改变入选资格或编造不在书库中的书。
5. 未标记不等于已证明未读。未开始优先须结合显式状态、进度和阅读时间字段；不把缺失信息伪造为0，不自动修改读完状态。

## 三个入口

- 正在阅读页：保留现有六个阅读状态与筛选／管理能力，新增推荐入口。以最近阅读／在读标记为主要上下文；无此信息时明确说明采用最近入库上下文，而非声称掌握阅读偏好。
- 书籍详情：第四标签按本书展示“相关阅读”及“拓展阅读”，各最多6本，数量随真实结果更新；仅看未开始、刷新、加入待读、两类负反馈和可选 AI 理由。
- 书末弹窗：仅依赖 Foliate 的结构性 `renderer.atEnd`，不能用进度百分比推断；初次打开／恢复到书末不立即弹出，须有本次有效阅读过程的非书末→书末变化。每次 Reader 挂载最多一次；不强制标记读完，不自动打开下一本，保留 CFI、草稿和离开保存屏障。

Web 与 BOOX 原生管理页共用推荐服务和 DTO；阅读器仍是现有 Web Reader，书末对话框在其中实现，不新增另一套阅读引擎或原生桥接入口。

## 排名与理由

- 本地特征仅使用书目元数据、已有标签／分类、受限长度的简介及现有阅读时间／状态字段；不读取正文、批注或笔记。
- 相关路：显式同作者、已知同类别、共同主题与词项向量综合；优先真正未开始的候选，同作者设占位上限。
- 拓展路：已知不同主类别、非同作者，并且存在可展示的共同主题／具体词项桥梁；过滤无信息泛词。与相关路互斥、跨类别分散，元数据不足时留空。
- 每个候选保留来源书、入选证据、真实阅读状态与可核对理由。分值只服务本地排序，不显示为语义准确率。
- 稀疏索引及结果只做有界内存缓存，输入摘要覆盖元数据、状态和反馈；刷新重新获取当前书库，不能静默复用失效结果。
- AI 只在明确点击“发送书目摘要生成理由”后调用当前配置。只发送当前书及这次候选的必要书目信息／简介摘要，不发送阅读轨迹、正文、笔记或整个书库。取消、超时、路由变更及晚到响应不更新错误上下文；错误保留本地理由。

## 持久化与安全边界

- 不新增数据库表、DDL 或模型依赖。
- 原生负反馈使用既有 NativeState settings JSON 的独立命名空间、字段存在性／值 CAS 和原有 receipt／未知结果语义；不覆盖 AI 设置，不吞噬读取失败。Web 使用本功能独立的每条反馈键，不重写整个设置对象。
- 负反馈类型区分“不感兴趣”和“关联不符”，限制数量并提供显式清空入口；不自动删除其他用户数据。
- 加入待读只改 readingStatus，采用受保护的条件更新／事务核验状态快照；不改进度、CFI、笔记、标签或文件。未知提交不自动重放。
- 后端重新核对候选 ID、来源书与缓存版本；不能由前端任意构造 AI 候选、反馈或旧状态覆盖。

## 失败模式与验收

冻结后以合成书目、模拟流和独立临时存储验证：空书库／少书／字段缺失／畸形字段、无可靠跨类桥梁、重复版本与明确分卷、作者及类别多样性、状态优先与过滤、负反馈读取失败及容量边界、缓存失效、候选删除或修改、取消／超时／晚到、确认状态冲突和未知结果不重放。

验证三个实际入口与真实 Foliate 书末条件；使用现有受保护 CFI、选择草稿和计时 oracle，不重跑已耗尽的历史故障方案。冻结2243本合成负载做宿主性能测量；报告硬件、输入、算法上限与实际结果，不把宿主结果移作 BOOX 性能承诺。
