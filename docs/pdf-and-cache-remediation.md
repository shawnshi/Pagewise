# PDF 书签、阅读助手与 Vite 缓存隔离

## PDF 操作

默认工具栏顺序不变：目录、搜索、书签、批注、阅读助手、朗读、排版。

- **书签**：按页保存，点击切换当前页标记；在批注抽屉的书签区跳转或删除。沿用既有 `AnnotationRec.kind=bookmark` 与 PDF 页定位格式，不改原高亮、笔记或源文件。保存中防止重复点击，写入失败不先改显示状态。
- **阅读助手**：使用设置中配置的同一模型。打开面板不发送请求；点击发送时仅发送书名/作者、页码、下方可编辑的当前页/选中文字、问题与本次同页对话，不读取整份 PDF、其他页或笔记。
- 文本上限 6000 字符，问题上限 1200，历史有界。扫描页无文本时明确提示，可手动粘贴；不自动上传图像或执行 OCR。模型配置缺失时提供设置入口。
- 翻页、关闭面板、原生 Back 或退出阅读器会取消进行中的回答；停止/失败的内容明确标记不完整，问题保留。输出按文本显示，不执行文档或模型返回的 HTML/指令。

主机合成测试与真实模型服务可用性是不同结果。未做实际服务验收时，不宣称真实模型已答复成功。

## 受控 Vite 入口

- `npm run dev/build/preview` 使用 `--configLoader runner`，避免配置 bundle 生成共享 `node_modules/.vite-temp`。
- 项目 Vite 配置将缓存放入当前工作树 `.cache`；TypeScript build-info 同样放入 `.cache/typescript`，不再写共享 `node_modules/.tmp`。
- 测试/语料脚本通过 `scripts/vite-isolated.mjs` 的 `createServer` 创建服务，保留真实配置、插件和 root，并为并发服务分配独立目录。`configFile:false` 同样受控。
- 路径校验同时检查逻辑路径与已存在前缀的真实路径，拒绝通过 symlink/junction 进入依赖目录的 root/cache；不通过路径校验时不创建目录或启动服务。

这些是受控入口与运行时检查，不是 OS 沙箱。手工绕过项目入口调用其他 Vite SDK/CLI，不自动获得隔离保证；需要明确 runner 与安全 cacheDir。不修改系统级 Vite、SDK、依赖版本或锁文件。

## RC-SCOPE-01 的整改语义

历史记录保持不变：旧归档 UI 测试曾违反当时约定，触及共享生成缓存。整改不能将那次执行改写为 PASS，也不能声称恢复了未知的事前缓存状态。

本轮仅将主工作区 `reader/node_modules/.vite` 与 `.vite-temp` 在无活动 Vite 进程时原子移动到任务 `.cache` 隔离备份，并逐文件验证内容不变。没有递归删除依赖，也没有清理旧 TypeScript `.tmp`。恢复只能在停止相关服务、确认原目标仍缺席且备份哈希一致后进行，不能覆盖新生成文件。

关闭本事件需要：真实同时服务、Vue 页面与官方构建执行后原两个共享路径仍缺席，隔离备份仍完整，源码/依赖保护检查通过。关闭状态应为 **CLOSED_WITH_REMEDIATION**，历史违规仍保留。旧归档 UI 的历史文案断言不因本次整改被重试或冒充通过。

任务的精确备份清单、执行日志、独立审查及关闭记录位于 `.cache/pdf-cache-20261018/`；本文件只定义使用与验收边界，不替代运行证据。此前实体尺量、墨水屏残影/闪烁及手指体验仍需人工观察，不能由截图或 CSS 像素换算代替。
