## 结论与范围

采用“灰阶语义＋单色描边＋低频整页交互”的方向，但不把硬件假设、性能目标或示意 API 当作已验证事实。先修改与阅读引擎无关的原生视觉底座，再整理藏书/在读，随后实现统计分页与派生封面，最后处理启动架构和刷新时序。

**已确定的架构选择 A：** 原生首页先启动，阅读时延迟加载现有 Web 阅读器。保留 EPUB/PDF 渲染、CFI、批注和仍有职责的 Rust／Web 桥；启动改造在 S5 单独实施，不再重复询问 A/B。本次选择没有授权完整纯原生阅读器迁移或持久化格式变更。

本轮已获授权的源代码范围不自动扩张为覆盖设备版本。当前可用 release 仍是 `Pagewise-1.7.0-bootstrap-fix-release.apk`，SHA-256 `da97fae8…ce6b46`。原1.6数据恢复、旧CFI/输入问题、真实书审计和完整S4仍按原记录保留。

## 一、逐项分析

以下代码现状以方案建立时为基线；实施后的当前状态以顶部进度和阶段报告为准。

### EINK-01：灰阶语义应保留，不能直接称为物理标定

16级是常见输入/显示能力，不代表所有设备、波形和快速模式均保持相同灰阶响应。给出的HEX也不全是 `0x00/0x11/…/0xFF` 网格值。以下为宿主脚本计算的**线性输入量化模型**，不是面板实测：

| 角色 | 输入HEX | 最近16级输入值 | 对白底对比度 | 工程处理 |
|---|---|---|---|---|
| 画布 | `#FFFFFF` | `#FFFFFF` | 1.00 | 保留纯白 |
| 表面 | `#FAFAFA` | `#FFFFFF` | 1.04 | 保留设计token，但不能仅靠它表示选中/分组 |
| 分割线 | `#D4D4D4` | `#CCCCCC` | 1.48 | 仅作装饰分隔；关键控件轮廓用黑色 |
| 主要文字 | `#000000` | `#000000` | 21.00 | 保留 |
| 次要文字 | `#4A4A4A` | `#444444` | 8.86 | 保留 |
| 禁用文字 | `#8C8C8C` | `#888888` | 3.36 | 仅表达真实禁用；重要说明仍需可读，保留原因/状态语义 |
| 划线/命中底色 | `#DCDCDC` | `#DDDDDD` | 1.37 | 配合下划线、边线或命中编号，不能只靠灰块 |

本阶段不改用户给定的浅色HEX；通过黑色轮廓、焦点框、选中标记补足浅灰不可见问题。保留已有深色主题选择，改成无彩色的黑白反转，不静默重置用户主题。原生控件使用dp，不能把“1px”直接当作所有DPI设备上的同一触控/轮廓尺寸。

### EINK-02：图标须同时控制路径、实际线宽和状态区分

现有 `NativeUi.kt` 已有统一Drawable入口，但仍混有填充路径、2.25视口单位强调和随绘制边界缩放的线宽。只把SVG字符串改成“2”不能保证实际为2dp；小图标中的封闭区域仍可能被线条挤满。

保留全部45个原生图标名称及别名，改为留白的单色描边路径。通过密度和Drawable实际缩放补偿，使普通/强调线宽分别为1.5dp/2dp；非正方形边界居中等比绘制。书签开/关仍使用不同形态，选中目的地继续保留现有指示，不用填黑代替所有状态。Web阅读器图标是后续独立检查面，本阶段不宣称已一并修改。

### EINK-03：封面抖动可做，PDF全局自动增强不可直接照搬

当前显示侧已有2工作线程、64队列和采样到不超过256尺寸的解码约束，但没有已证的灰度抖动、解码缓存或排队取消。RGB_565不是Floyd–Steinberg算法，也不能证明输出只有16个中性灰值。导入侧会生成持久化JPEG封面，这与可丢弃的显示缓存不同。

实施方案：原始书籍/封面保持不变，在应用缓存目录生成派生图；先按实际目标尺寸采样，再执行版本化亮度转换、16级量化和Floyd–Steinberg误差扩散。使用两行误差缓冲、有限并发和请求代次，缓存键包含源身份/版本、尺寸及算法版本，内存和磁盘均设上限。透明像素先按白底合成，避免黑边。

严格16级输出不能使用会重新引入灰阶/色偏的有损WebP；使用无损WebP，旧API用无损PNG等合规回退。ARGB_8888与解码后颜色集合需要测试，不能把RGB_565当作无损灰阶容器。C++/NDK只有在Kotlin原型的真实尺寸/耗时/分配基线证明不足后再引入，避免先增加构建和JNI边界。

“直方图均衡化”和“对比度线性拉伸”不是同一算法，也不保证背景变白、线条变黑。PDF文字/矢量层不应整体抖动；彩色图表的系列、图例、细线和医学/证据图像可能因增强改变含义。图表增强应是可关闭、明确标识的显示选项，默认不改原文件，也不自动处理所有正文图像。

### EINK-04：启动应按可观测阶段优化，不能承诺0ms

代码证据显示：`MainActivity.super.onCreate()`先进入Wry/Rust生命周期，随后初始化Onyx桥；原生管理页虽为Android Views，其ready检查、导航和部分回执仍依赖现有桥和Web处理器。因此不能直接把现有Controller搬到 `Application.onCreate()` 就称为纯原生直启。

Android官方区分首次显示TTID和内容就绪TTFD。静态Splash可以减少过渡，不会让进程调度、绘制和电子纸刷新变成0ms；`decorView.post`只保证消息调度，不保证首帧或物理面板完成。500～750ms、2.2～3.0s、180MB均暂列待测假设。现有295ms等Activity启动回执也不是内容就绪耗时。本次设备元数据探针退出1，后续最小能力探针明确返回 `device '9D7BC516' not found`。未取得可用内存样本，不能据此填写PSS或冷启动峰值。

先做：应用内纯白/黑Logo静态窗口、去除冗余过渡、统一首个可见表面；记录进程启动、native-state就绪、书库就绪、首帧提交和可交互信号。内存分别记录主进程与可归属的WebView renderer，固定书库规模、主题、方向和WebView版本，分开报告冷启动/热恢复及P50/P95。不能把没有renderer归属证据的系统总值算进应用预算。

**已发现的刷新路由问题：** `MainActivity`申请GU，但 `scheduleOverlayRepaint`除GC外均映射到REGAL。当前反射调用还可能吞掉不支持的签名，状态不等于物理刷新成功。先修模式解析和能力回执，再绑定当前宿主/当前视图代次的绘制或提交信号，避免仅靠120ms延时或重复post刷新。未在本地证实 `applyEntity`、`EINK_MODE_REGAL` 的SDK声明，不直接新增这些调用。没有硬件回执/外部摄影就不宣称消除了残影。

已选择的 Native-first 路径仍需梳理 ready、存储引导和回执所有权；完整 Native 阅读器不在本轮范围，不能删除 Rust 和 Web 后留下原有路由。

### EINK-05：藏书改为“标题摘要＋类别入口＋紧凑书目”

现有藏书已经分页，并非无限滚动；页内ScrollView是另一层问题。先基于真实可用高度、字体和封面行高计算单屏容量，默认尽量整页翻动，同时保留大字号/键盘/无障碍所需的溢出回退，不能靠裁切强制单屏。方向或字号变化需重新校验分页/选择快照，避免旧页号和旧token继续操作。

- 数量、累计时间移到“藏书”标题之后；元数据回执须受当前页面epoch/owner保护，错误时不能把旧摘要当新结果。
- 代码中现有横排控件实际为“排序／筛选／管理”，没有同名“关联”按钮。本方案把这些能力收纳到右上更多菜单，正文突出类别标签；不删除管理、导入、文件夹或关联笔记等后台能力。
- 类别标签已有实现，但“仅一个类别且覆盖全库”时被隐藏。应重排并取消该抑制，显示有书的类别，而不是再造第二套分类。现有facet计数来自全库；必须标清计数范围，不能把它冒称当前搜索结果数量。零计数不显示，切换后回到第一页、清除旧选择并绑定新token，不擅自改变原查询组合。
- `nativeLibraryActions.ts` 的 `libraryPage` DTO目前未带 `publisher/publicationDate`；`NativePagesController.bookRow` 又只在reading分支尝试显示这些字段。需要补齐DTO并修改藏书行，不能只加TextView。作者后追加出版社和出版时间，缺值不制造分隔符；窄屏自然换行，不以省略关键信息来凑行。
- 封面先使用上述派生缓存。原始cover路径、书籍ID、分类JSON和批注关联不改。

### EINK-06：正在阅读压缩展示，但保留真实排序/导航合同

移除“快速接续阅读进度与近期记录”的介绍区和实际名为“筛选与管理”的入口；管理能力继续在藏书页可达，不删除后台接口。现有百分比在单独进度行，上次阅读/累计在另一行：应将百分比并入同一可换行元数据行，去掉重复百分比独立行。沿用 `hasProgress` 判定，不把缺失时间/进度显示成已确认的0。保留阅读入口、书籍身份、保存屏障和原CFI，不在布局修改中重写阅读进度逻辑。

### EINK-07：统计采用离散等级、可辨纹理和固定周期

热力图按原有秒数派生显示等级，不改变持久化口径：0为白底黑框；0＜秒数≤1800为低等级；1800＜秒数≤3600为中等级；＞3600为黑实心。小于1分钟但大于0的记录不能丢成未阅读。无效或未完整加载的数据必须显示未知/错误，而不是白色0。

低/中等级使用可辨的稀疏点阵/交错纹理，纹理单元按dp和实际尺寸选择，不盲用1物理像素微网格；配合时长图例和可访问描述。四级阈值固定，不能随月份最大值重新缩放，让不同月份保持可比较。

周/月/年按固定周期前后切换，默认整屏报告；物理左右键只在统计页无输入框/弹窗时处理。A5作为阅读报告的叙事/比例参考，不强锁148×210mm导致横屏裁切；横竖屏分别布局，必要时分成多张报告卡。刷新在当前报告真正提交后申请一次，实际波形受SDK能力约束。

翻页数、平均停留、手写字数暂不塞入既有统计：需要先定义“成功的物理翻页”与程序跳转/重排/自动翻页区别；平均停留的分母是有效曝光页还是翻页事件；笔画不等于字符，现有文本批注也不证明来自手写。历史无事件数据时显示“从新版本起记录/不可用”，不能伪造历史0。这部分另有事件Schema、迁移、隐私和验收门。

## 二、实施顺序与验收

1. **S1 共享视觉底座（源码与复审完成）**：限定 `NativeUi.kt`、`NativeUiMetrics.kt` 及对应测试。保留主题选择与所有图标名称，灰阶token、单色描边、实际dp线宽、无阴影和既有触控目标。执行生产Kotlin不变量、全图标有效性、浏览器矢量画廊、布局回归和独立审查。设备渲染/物理灰阶未验证时不称实机验收完成。
2. **S2 藏书/在读布局（源码及合成 Android 验收完成）**：标题摘要、类别与元数据、精简在读行及 More 已实现；真实 Activity 最终28/28、相关回归34/34，独立复审 `scoped_OK`。修复大字号标题省略和窄屏正文被按钮挤压；覆盖合成320/992dp、1／1.8倍字体，不代表生产或物理墨水屏验收。本切片保留12／24页容量及 selection-token 协议，自适应整页容量尚未实现。未读取真实书。
3. **S3 统计报告**：四级纹理、固定周期与按键分页；用边界秒数、跨年/月/闰日、空数据、加载失败和当前宿主代次测试。暂不新增未定义的统计口径。
4. **S4 派生封面**：先做尺寸/缓存/后台取消，再加入16级抖动；以合成梯度、文字封面、透明像素和超大输入验证颜色集合、内存上限、重复请求和缓存失效。原图始终可恢复。
5. **S5 启动/EPD**：先冻结性能基线及正确刷新路由，再按已确定的 A 实现 Native-first 首页与阅读时延迟加载既有 Web 阅读器。保留恢复点、旧契约和干净上下文审查；不执行完整纯 Native 阅读器替换。
6. **S6 新指标**：确认事件定义/数据源之后另行版本化，不把展示改版顺带变成统计迁移。

本轮不合并、不推送、不升级依赖，不自动覆盖设备 APK。A 已确认，不再作为阻塞。旧 S2 setup 三次失败的历史保留；新获批的真实 Activity 计划已完成，在679.6秒内关闭专用实例。当前 scoped 结论不扩大为生产安装、Web／数据库端到端或物理 EPD 验收。
